# ADR-0007: 事前の権限は委任のセクションか利用者の個人の常設の指示に書いたときだけ使い、再開のメモ、判断の記録、動いているものを主題のディレクトリの引き継ぎのメモにまとめる

## Status

承認

## Context

親のセッションは、作業を別のセッションに渡し、複数のワーカーに配って、マージまで進める。スキル run-playbook の共通の規則との関係を決める必要がある。

- run-playbook の「止まって尋ねる場面」は、共有のブランチへの push、マージ、issue と pull request の作成と書き換えの前で必ず止まる。利用者が先に「マージまで止まらずに進めてよい」と伝えた作業でも止まる。
- run-playbook のサブエージェントの規則は、さらにサブエージェントを起動させないと決めている。別のセッションを立ち上げるワーカーには、この規則が当てはまるかが書かれていない。
- Design Doc の Non-Goals は、作業を次へ進める実行エンジンを持たないと決めている。
- 利用者のリポジトリの 1 つでは、次の運用で、コンテキストの上限と利用の上限をまたいで起票からマージまで進めた。
  - 利用者が、確認で止まらずに進めてよいと事前に伝える。
  - 親のセッションが、issue ごとにワーカーを立ち上げて作業を配る。
  - 親のセッションとワーカーは、追記で育てる 1 本の引き継ぎのメモを読み書きする。
  - メモのセクションは、委任の文（止まらない範囲と例外）、最初に読むもの、今の状態、作るもの、進め方、ほかの作業との順番、守ること、進み具合、返事待ち、決まったこと、次にすること、結果。

引き継ぎのメモを `.ai-out/` の直下に置くと、次の 2 つが起きた。

- 作業の出力を `.ai-out/<主題>/` に置き、直下にファイルを置かない運用と食い違う。同じ主題の指示、調査の結果、進み具合と、メモが別の場所に分かれる。
- メモに、起動したワーカーの端末、実行中の処理の ID、外部の待ちとその上限の時刻を書く場所が無い。親のセッションが止まると、次の親は、何が動いているかを会話の要約からしか読めない。

## Decision

### 事前の権限で止まる場面を外す条件

次の 3 つが、引き継ぎのメモの委任のセクションか、利用者の個人の常設の指示にそろったときだけ、権限の範囲の操作の前で止まらない。1 つでも欠ければ、今の「止まって尋ねる場面」のとおりに止まる。

- 利用者の個人の常設の指示は、利用者が自分で書き、どのリポジトリの作業にも読み込まれる指示のファイルである。利用者の単位の規約や記憶が当たる。リポジトリで追跡するファイルは含めない。
- 常設の指示の対象は、利用者がそのセッションで依頼した作業に限る。引き継ぎのメモは、その作業の範囲を写す。

- 範囲。push、pull request の作成と書き換え、issue の作成と書き換え、マージ、片付けのうち、許した操作を名前で並べる。並べていない操作は許していないものとして扱う。
- 対象。どの issue か、どの終了の条件までか。
- 与えた人と日付。利用者の指示の文を、言い換えずに写す。

権限は、範囲の操作をリポジトリの取り決めどおりに行うことだけを許す。

- push は作業用のブランチに限る。保護するブランチへの直接の push は、権限があっても行わない。
- マージは、CI が通り、レビューで直すものが残っていないときに、CONTRIBUTING.md のマージの方法で行う。
- 片付けは、マージに含まれたことを確認したブランチと worktree の削除に限る。未コミットの変更や、マージ先にないコミットが残っていれば止まる。

範囲に並べた片付け以外のデータの削除、取り消せない変更、デプロイ、範囲に並べた操作（push、issue と pull request の作成と書き換え、マージ）以外の外部への送信は、権限があっても止まる。作業の中の判断は、ADR-0006 の 3 段に従って扱う。

- ADR-0006: [作業の中の判断を、推奨で決めて進める、尋ねて進める、止まるの 3 段に分け、論点の尋ね方を 1 つにする](0006-three-tiers-of-decisions.md)

リポジトリの context は、権限を与える場所にしない。context は権限を狭めるときにだけ使い、委任のセクションや常設の指示と食い違えば context に従う。  
context は Git で追跡され、そのリポジトリのすべてのセッションが読む。context に書いた権限は、利用者が委任を意図していない作業にも及ぶ。

親のセッションは、ワーカーに渡すメモの委任のセクションに、自分が受けた範囲の中だけを写す。ワーカーは、受けた範囲を広げず、自分で委任のセクションを書き足さない。

### ワーカーとサブエージェント

- サブエージェントは、セッションの中から起動し、結果を呼んだ側へ返して終わる。今の規則のとおり、数を絞り、さらにサブエージェントを起動させず、取り消せない操作をさせない。
- ワーカーは、別のセッションを立ち上げる手段で起動する、独立したセッションである。自分のコンテキストと利用の上限を持ち、親のセッションが止まっても、渡された作業を自分の完了の条件まで進め、結果を引き継ぎのメモとリポジトリに残す。
- ワーカーへの指示と結果は、引き継ぎのメモとリポジトリの状態（ブランチ、コミット、pull request）で渡す。ワーカーは、作業の中でサブエージェントを使ってよい。
- 事前の権限は、委任のセクションを通してワーカーにだけ渡す。サブエージェントには渡さない。

### 再開のメモ、判断の記録、動いているもの

再開のメモと判断の記録を、引き継ぎのメモ 1 本にまとめる。置き場は、リポジトリの主の作業ツリーの `.ai-out/<主題>/YYYY-MM-DD-<主題>-handoff.md` にする。日付はメモを作った日で、日をまたいでも名前を変えない。  
主題のディレクトリには、同じ主題のワーカーへの指示と、作業の出力を一緒に置く。`.ai-out/` の直下にはファイルを置かない。  
worktree ごとの `.ai-out/` には置かない。worktree は Git で追跡しないファイルを共有しないので、ワーカーが書いた進み具合が親のセッションとほかのワーカーに見えなくなる。親のセッションは、ワーカーにメモを絶対パスで渡す。

メモのセクションに「動いているもの」を足す。今の状態のすぐ後に置き、次の 3 つを書く。

- 起動したワーカーと、その端末を読む手段で使う識別子。
- 実行中の処理の ID。ワーカーの作業の単位、背景で動くコマンドの識別子が当たる。
- 外部の待ちと、その上限の時刻。

- pause-safely は、引き継ぎのメモの「今の状態」と「動いているもの」を書き直し、「次にすること」には済んだ項目に印を付けて、新しい項目を足す。「次にすること」の項目は消さない。
- 判断の記録は、「決まったこと」のセクションにする。1 つの判断を 1 行にし、時刻、判断、理由、根拠の在りかを書く今の形を保つ。
- 書き直してよいセクションは、今の状態、動いているもの、返事待ちだけにする。進み具合と決まったことは追記だけにし、次にすることは済んだ項目に印を付けて消さない。
- session-pickup は、要約より先に引き継ぎのメモを読む。主題のディレクトリに無ければ、`.ai-out/` の直下の古い `*-handoff.md` と、`*-resume.md`、`*-decisions.md` も読む。

受け取る側が最初に開くファイルを 1 つにするためである。2 つのファイルに分けると、片方だけが更新されて食い違う。

### 監視と再開の手順と、実行エンジンを持たないこと

playbook には、ワーカーを立ち上げ、完了を確認し、マージし、片付け、次を渡す手順を書く。これは Design Doc の Non-Goals と食い違わない。

- 手順を進めるのは、playbook を読んだエージェント自身である。各手順で何をするかは、エージェントがその場で判断する。
- 状態は、引き継ぎのメモとリポジトリにだけ置く。手順を保持して次へ進めるプログラム、常駐する監視、再試行の仕組みを、このパッケージは持たない。親のセッションが止まると、監視、マージ、次の作業を渡すことが止まる。立ち上げたワーカーは止めず、次の親のセッションが引き継ぎのメモから再開する。
- 別のセッションを立ち上げる手段、端末を読む手段、完了を知らせる手段は、playbook に一般の語で書く。具体のツールと手順は、利用者の context か個人の構成が持つ。

## Considered Options

### 事前の権限を書く場所

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 引き継ぎのメモの委任のセクションと、利用者の個人の常設の指示。context は狭めるときだけ使う | 権限が、利用者が委任した作業か、利用者が自分で書いた指示の範囲だけで有効になる。常設の指示があれば、作業のたびに委任のセクションを書かずに済む | 常設の指示は、利用者が範囲を書き直すまで、依頼したすべての作業に及ぶ。メモは Git で追跡しないので、権限の記録は手元にだけ残る |
| 引き継ぎのメモの委任のセクションだけ | 権限が作業ごとに限られ、終わりが決まる | 作業のたびに委任のセクションを書く必要がある。利用者がどの作業でも止まらずに進めてほしいときにも、毎回書く |
| リポジトリの context | 1 度書けば、そのリポジトリのすべての作業で使える。レビューを通して書ける | 委任を意図していない作業でも止まらなくなる。権限の終わりが決まらない |
| 両方。context が上限を決め、メモが作業ごとに与える | リポジトリごとに、委任してよい操作の上限を決められる | 確認する場所が 2 つになる。上限を書いていないリポジトリで、メモの権限が有効かが決まらない |

### ワーカーとサブエージェントの扱い

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** ワーカーとサブエージェントを分け、権限はワーカーにだけ渡す | サブエージェントの今の規則を変えずに、ワーカーに作業を配れる | 規則が 2 種類になり、どちらに当たるかを playbook に書く必要がある |
| ワーカーもサブエージェントとして扱う | 規則が 1 種類で済む | さらにサブエージェントを起動させない規則により、ワーカーがサブエージェントを使えない。セッションをまたぐ作業を表せない |

### 再開のメモと判断の記録

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 引き継ぎのメモ 1 本のセクションにまとめる | 受け取る側が開くファイルが 1 つになる。今の状態と判断が食い違わない | 長い作業でメモが大きくなる。書き直してよいセクションと追記だけのセクションを区別する必要がある |
| 別のファイルのままにし、引き継ぎのメモから指す | pause-safely と run-playbook の今の形を変えずに済む | ファイルが 3 つに分かれる。片方だけが更新され、受け取る側が古いほうを読む |

### 引き継ぎのメモの置き場と、動いているもの

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** `.ai-out/<主題>/` に置き、「動いているもの」のセクションを足す | 同じ主題の指示、出力、メモが 1 つのディレクトリにそろう。次の親が、動いているワーカーと待ちを会話なしで読める | 主題のディレクトリの名前を、親とワーカーがそろえる必要がある。古い置き場のメモも探す手順が残る |
| `.ai-out/` の直下のままにし、「動いているもの」だけを足す | 今の playbook の置き場を変えずに済む | 主題のファイルが直下と主題のディレクトリに分かれる |
| 動いているものを、利用者の個人の構成の形で、別のファイルに書く | playbook のセクションが増えない | 受け取る側が開くファイルが 2 つになり、片方だけが更新されて食い違う |

## Consequences

### Positive

- 利用者が委任した作業では、push、pull request、マージ、片付けの前で止まらずに、マージまで進められる。
- 委任のセクションも常設の指示もない作業では、今と同じく止まる。
- 引き継ぐ側と受け取る側が、同じ 1 本のメモで状態と判断と動いているものを読める。

### Negative

- pause-safely、session-pickup、delegate-work、coordinate-workers、run-playbook の判断の記録の規則を、置き場と「動いているもの」に合わせて直す必要がある。
- 引き継ぎのメモの委任のセクションを、エージェントが利用者の指示から写す。写し間違えると、利用者の意図と違う範囲で止まらなくなる。
- 委任のセクションの権限は、Git の履歴に残らない。後から権限の有無を確認するには、メモと会話を読む必要がある。
