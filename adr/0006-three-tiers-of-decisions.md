# ADR-0006: 作業の中の判断を、推奨で決めて進める、尋ねて進める、止まるの 3 段に分け、論点の尋ね方を 1 つにする

## Status

承認

## Context

スキル run-playbook の共通の規則は、利用者だけが決められる判断（製品の方針、範囲、優先順位）を、推奨の案を添えて尋ねると決めている。playbook autonomous-run は、その判断の前で全体を止め、pause-safely を行う。

- 推奨で決めて進めてよい小さな判断の区分が無い。見た目、文言、内部の命名のような判断でも、尋ねるか、決めた理由を残さずに決めるかのどちらかになる。
- 論点が 1 つ出ると、その論点に依存しない作業も止まる。利用者が離れている間の作業では、利用者が戻るまで何も進まない。
- 尋ねる先と、1 つの論点に何を書くかが決まっていない。会話、issue のコメント、引き継ぎのメモの「返事待ち」に、形の違う問いが分かれて残る。

利用者が離れている間に作業を進めた運用では、見た目や文言の小さな決定を推奨で決めて後でまとめて伝え、業務の語、権限、データ、仕様だけを尋ねる区分で進めた。issue と設計の文書に無い動きも、決めずに尋ねた。  
この区分は playbook に無く、playbook を使うほかの利用者には届かない。

事前の権限で止まる場面を外す条件は、ADR-0007 で決めている。取り消せない操作で権限の範囲に無いものは、権限があっても止まる。

- ADR-0007: [事前の権限は委任のセクションか利用者の個人の常設の指示に書いたときだけ使い、再開のメモ、判断の記録、動いているものを主題のディレクトリの引き継ぎのメモにまとめる](0007-pre-granted-permission-and-handoff-memo-placement.md)

## Decision

### 判断の 3 段

作業の中の判断を、次の 3 段に分ける。どの段にも当たらない判断は、2 段目として扱う。

| 段 | 当たる判断 | 扱い |
| --- | --- | --- |
| 1. 推奨で決めて進める | 見た目、文言、内部の命名のような、後から戻せる小さな判断 | 推奨の案で決めて進め、引き継ぎのメモの「決まったこと」に記録する。区切り（pull request、報告、親への完了の通知）で、まとめて伝える。pull request では「レビューしてほしい点」に書く |
| 2. 尋ねて進める | issue と設計の文書に無い動き、業務の語、権限、データの扱い、範囲、優先順位 | 決めずに尋ねる。答えを待つ間は、その論点に依存しない作業を進める。依存する作業しか残らなければ止まる |
| 3. 止まる | 取り消せない操作で、事前の権限の範囲に無いもの | 操作の前で止まり、利用者の明示の指示を待つ。条件は ADR-0007 に従う |

- 委任のセクションが無いとき、1 段目の範囲は表の種類だけにする。2 段目の判断を推奨で決めてよいのは、委任のセクションに、利用者が推奨で決めてよい判断の種類を名前で並べたときだけにする。並べ方は、事前の権限と同じく、利用者の指示の文を言い換えずに写す。
- リポジトリの context は、1 段目の範囲を狭めるときにだけ使う。context で 1 段目を広げない。context は、利用者が委任を意図していない作業にも読まれるためである。
- 3 段目は、委任のセクションでも外せない。ADR-0007 の、権限があっても止まる操作の一覧に従う。
- 実行すれば分かる事実（動き、出力、性能、見た目）は判断に含めず、今のとおり尋ねずに確認する。

### 論点の尋ね方

2 段目の論点は、1 つずつ、次の形で尋ねる。

- 選択肢を 2〜4 つ並べる。
- 推奨の案と、その理由を書く。
- 決まらないと進めない作業を書く。決まるまでに進める作業があれば、それも書く。

尋ねる先は、次のとおり。

- 利用者と対話しているセッションは、会話で尋ねる。
- ワーカーは、親のセッションに、完了の通知と同じ手段で尋ねる。親は、委任の範囲と 1 段目で答えられるものだけに答え、残りを利用者に尋ねる。
- どちらの場合も、同じ形の論点を、引き継ぎのメモの「返事待ち」に書く。答えを受けたら、「返事待ち」から消し、「決まったこと」に 1 行を足す。

## Considered Options

| 選択肢 | 強み | 弱み |
| --- | --- | --- |
| **採用:** 3 段に分け、1 段目の既定を狭く取り、委任のセクションで広げる | 小さな判断で止まらない。尋ねている間もほかの作業が進む。広げる範囲が作業ごとに記録に残る | 1 段目と 2 段目の境目を、エージェントが判断する。誤って 1 段目にした判断は、区切りで伝えるまで利用者に見えない |
| 運用で使った区分を、そのまま run-playbook の共通の規則に移す | 運用と規則がそろう | 推奨で決めてよい範囲を、作業ごとに広げる手段が無い |
| 推奨で決めてよい範囲を、委任のセクションに書いたときだけにする | 利用者が許した判断だけが決まる | 委任のセクションが無いと、見た目や文言でも止まり、今と変わらない |
| 今のとおり、利用者だけが決められる判断はすべて尋ね、尋ねたら止まる | 判断を誤って決めることが無い | 論点 1 つで全体が止まる。利用者が離れている間の作業が進まない |

## Consequences

### Positive

- 利用者が離れている間も、論点に依存しない作業が進む。
- 尋ねる論点が 1 つの形にそろい、利用者は選択肢と推奨から答えを選べる。
- 推奨で決めた小さな判断が、記録と pull request に残り、後から戻せる。

### Negative

- スキル run-playbook の止まって尋ねる場面と、playbook autonomous-run、coordinate-workers を、この 3 段に合わせて直す必要がある。
- 1 段目に当たるかの判断を誤ると、利用者が決めるべき判断を、エージェントが決めてしまう。区切りで伝えるまで、利用者は気づかない。
