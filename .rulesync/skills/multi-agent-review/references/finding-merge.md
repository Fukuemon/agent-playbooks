# Finding Merge

複数エージェントの指摘を 1 つのレポートへ統合する規則。

## 手順

1. **パース**: 各エージェント出力を `review-prompt.md` と同一の行文法 (`- [重大度: high/medium/low] <file:line> — <指摘> / 根拠: <...> / 提案: <...>`) で読み取る。`NO FINDINGS` は指摘なしとして扱う。文法は review-prompt 側と一字一句一致させる (片方を変えたら両方更新)。
2. **正規化**: `file:line` を正規化 (リポジトリ root からの相対パス・行番号) し、**同一ファイルかつ同一 hunk 内 (目安 ±3 行)** で趣旨が同一の指摘は同一とみなす。
3. **dedupe / 合意数**: 同一指摘を 1 件に統合し、何エージェントが挙げたか (`agreement`) を数える。
4. **重大度の確定**: エージェント間で割れたら **高い方** を採る (保守的)。
5. **ランク付け**: `重大度` → `agreement` の順で降順ソートする。

## 出力レポート構成

```text
## Multi-agent review (<timestamp>)

<status テーブル — agent / status / retries / output>

### 統合指摘 (重大度順)
- [high ×3] src/foo.ts:42 — <指摘> / 根拠 / 提案   ← ×N は合意エージェント数
- [medium ×2] ...

### 単一エージェントのみ (未合意)
- [low ×1, by cursor] ...

### エージェント間の相違
- src/bar.ts:10 — claude は問題なし / codex は要修正 (<相違の要約>)

### 注記
- skipped: <agent> (<理由>)。本レポートは N/M エージェントの結果に基づく部分結果。
```

## 規則

- `agreement` が高い指摘ほど信頼度が高い。`×1` の指摘は「未合意」セクションに分け、断定しない。
- 重大度が割れた点・結論が割れた点は「相違」として必ず残す (握りつぶさない)。
- 根拠 `file:line` を持たない指摘はマージせず、参考としてのみ列挙する。ただし **spec (散文) 対象では行番号が無いため `path#見出し` / anchor を `file:line` 相当のアンカーとして許容**し、同一アンカー + 同一趣旨を同一指摘として dedupe する (コード差分では従来どおり `file:line`)。
- スキップされたエージェントを必ず注記し、何分のいくつの結果かを明示する。
