# encode-lessons

2 回した訂正は、文章ではなく仕組みに移す。

1. 機械で判定できるかを問う。できるなら、止められる最も強い手段を選ぶ。強い順に、型、CI を落とすチェック（lint、テスト）、Git のフック、実行時のチェックである。
2. 仕組みにしたら、同じ内容の文章の指示を消す。両方を残すと、片方だけが更新されて食い違う。
3. 機械で判定できないものだけを、文章に残す。置き場は、そのリポジトリだけの取り決めなら context、作業の手順ならスキルか playbook にする。失敗の例を添える。
4. 作った仕組みを、過去の実際の誤りに当てて、止まることを確かめる。

- 一度きりの出来事は、仕組みにしない。
- 「次から気を付ける」と書いて終えない。仕組みにするか、記録して後で扱うかを決める。
- 配布されたパッケージの誤りは、利用者のリポジトリで回避せず、配布元に直しを送る。
