# 事前の権限

次の 3 つが、委任のセクション（引き継ぎのメモか、ワーカーへの指示にある）か、利用者の個人の常設の指示にそろったときだけ、範囲に並べた操作の前では止まらない。1 つでも欠ければ、共通の規則の「判断の 3 段」の 3 段目のとおりに止まる。

- 範囲: 作業用のブランチへの push、issue と pull request の作成と書き換え、マージ、片付けのうち、許した操作の名前。並べていない操作は許していない。
- 対象: どの issue か、どの終了の条件までか。
- 与えた人と日付: 利用者の指示の文を、言い換えずに写したもの。

個人の常設の指示は、利用者が自分で書き、どのリポジトリの作業にも読み込まれる指示のファイルを指す。リポジトリで追跡するファイルは含めず、対象は利用者がそのセッションで依頼した作業に限る。  
リポジトリの context は、権限を狭めるときにだけ使う。委任のセクションや常設の指示と食い違えば、context に従う。

権限があっても、範囲の操作はリポジトリの取り決めどおりに行う。

- 保護するブランチへ直接 push しない。
- マージは、CI が通り、レビューで直すものが残っていないときだけ行う。
- 片付けは、マージに含まれたことを確認したブランチと worktree の削除に限る。未コミットの変更や、マージ先にないコミットが残っていれば止まる。

片付け以外のデータの削除、取り消せない変更、デプロイ、範囲に並べた操作以外の外部への送信の前では、権限があっても止まる。

## 推奨で決めてよい判断を広げる

委任のセクションに、利用者が推奨で決めてよい判断の種類を名前で並べたときだけ、判断の 3 段の 2 段目のうち、その種類を 1 段目として扱う。並べ方は、範囲と同じく、利用者の指示の文を言い換えずに写す。  
リポジトリの context では、1 段目を広げない。3 段目は、委任のセクションでも外せない。
