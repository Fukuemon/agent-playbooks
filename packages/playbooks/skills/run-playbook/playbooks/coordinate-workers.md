# coordinate-workers

**担当:** 依存を並べた複数の作業をワーカーに配り、取り込みと片付けまでを、終了の条件まで繰り返す。親のセッションがこの手順を進める。  
1 つの作業を渡すだけなら、delegate-work を使う。手順を自動で進めるプログラムや常駐の監視は、このパッケージにはない。

1. 終了の条件を、合否が出る形で書く。「対象の issue の pull request がすべて取り込まれ、worktree が片付いている」のように書く。置き場は、引き継ぎのメモの「作るもの」にする。メモがなければ、delegate-work の手順 3 で作る。
2. 作業を並べる。1 つの作業は、単独で取り込める単位にする。作業ごとの依存（先に取り込まれる必要がある作業）を、メモの「ほかの作業との順番」に書く。依存のない作業は、並べて配る。
3. 並べる作業の資源を分ける。worktree、ブランチ、コンテナの名前、ポート、イメージ名、一時のディレクトリを作業ごとに別の名前にし、ワーカーへの指示の「制約」に書く。ほかの作業や他人が作った資源は消さない。
4. 配る。依存が解けた作業ごとに、delegate-work でワーカーへの指示を作り、ワーカーを起動する。
5. 完了を待つ。待つ前に bound-every-wait を読み、上限を決める。完了は、ワーカーの完了の通知か、メモの「進み具合」に足された行で受ける。
6. 上限を過ぎても完了がないワーカーは、端末を読む手段で様子を見る。ワーカーの worktree を、親が代わりに書き換えない。次のどれかに当たれば、止まっていると見る。
   - 入力や確認を待っている。委任の範囲の中で答えられるものだけ答える。範囲の外のものは、メモの「返事待ち」に書き、利用者に尋ねる。
   - 利用の上限に当たっている。再開できる時刻をメモの「進み具合」に書き、ほかの作業を進める。
   - 同じコマンドが長く終わらない、出力が長く変わらない。ワーカーに状態を尋ね、答えがなければ利用者に尋ねる。
7. 完了を確認する。ワーカーの報告は自己申告として扱う。pull request の CI の結果と差分を自分で読み、受け入れの条件を満たすこと、持ち分の外のファイルを変えていないことを確認する。足りなければ、直す点をワーカーに返す。prove-it-works を読む。
8. 取り込む。委任の範囲に取り込みがあれば、CONTRIBUTING.md のマージの方法で取り込む。範囲になければ止まって尋ねる。
9. 取り込んだ状態を確認する。pull request が取り込まれたことと、取り込み先の CI の結果を見る。取り込みと片付けを、1 行のコマンドでつながない。取り込みが失敗しても、片付けが動いてしまう。
10. 片付ける。委任の範囲に片付けがあれば、取り込みに含まれたことを確認したブランチと worktree だけを消す。未コミットの変更や、取り込み先にないコミットが残っていれば止まる。
11. メモの「進み具合」「決まったこと」「次にすること」を更新し、手順 4 に戻る。終了の条件を満たしたら止まる。
12. 親のセッションが途中で止まるとき（コンテキストや利用の上限、中断）は、pause-safely を行う。起動したワーカーは止めない。次の親のセッションが、session-pickup でメモから再開する。

**止まる:** 委任の範囲にない操作の前。利用者だけが決められる判断。ワーカーが範囲の外の判断を尋ねたとき。

**返答に書くこと:** 終了の条件と最後の状態、作業ごとの pull request とマージのコミット、片付けたもの、止まったワーカーとその扱い、未実施のことと理由、引き継ぎのメモの絶対パス。
