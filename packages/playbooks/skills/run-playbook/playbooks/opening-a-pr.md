# opening-a-pr

**担当:** 終えた変更を、すぐレビューできる pull request にする。ほかの playbook の最後に呼ぶ。  
pull request の指摘への対応は、pr-follow-up が行う。

1. 作業は、統合ブランチから切った作業用のブランチで行う。保護するブランチに直接コミットしない。ブランチの名前は CONTRIBUTING.md に従う。
2. 変更を関心ごとのコミットに分ける。分け方とメッセージは、スキル write-commit に従う。
   - コミットのフックが失敗したら、原因を直してからコミットし直す。フックを飛ばさない。
   - 生成物の差分を確かめるフックがある repo では、生成先のファイルを含むコミットを先に作る。
3. push の前に、CONTRIBUTING.md の「コミットするとき」と CI が実行するチェックを、手元で実行する。
4. 題と本文を下書きする。書き方は、スキル write-issue-pr に従う。本文には、確かめたことと確かめていないこと、決まっていないことを書く。
5. push と pull request の作成の前に、利用者の指示を待つ。
6. 指示を受けて push し、pull request を作る。下書き（Draft）で作るかは、CONTRIBUTING.md の取り決めに従う。取り決めがなければ、レビューできる状態で作る。
7. CI の結果を待つ。失敗したら pr-follow-up を行う。

**止まる:** 手順 5 で push と作成の指示を待つとき。

**返答に書くこと:** pull request の URL、コミットの一覧、CI の結果。
