# correct

**担当:** 繰り返す誤りを、リポジトリの仕組みで起こせなくする。文章の規則は最後の手段にする。encode-lessons を読む。  
前提として、次にこのリポジトリを触るのは、開いたファイルしか見ず、近くの例をまね、通る中で最も短い道を選ぶエージェントだと考える。

1. 誤りを集める。最近のコミット、取り消したコミット、レビューのコメント、回避策を説明するコメント、利用者の訂正から集め、種類ごとにまとめる。扱うのは、2 回以上起きた種類だけにする。
2. 種類ごとに、止められる最も上の手段を選ぶ。上から順に強い。
   - 構造: 状態の持ち主を 1 つにする、やり方を 1 つにする、内部の実装を外から使えなくする、一覧を 1 か所に置く、古いやり方を消す。
   - 型: 誤った状態を型で書けなくする。
   - CI を落とすチェック: lint の規則、Git のフック、CI の手順。lint のメッセージには、代わりに使うものの名前を書く。
   - 振る舞いのテスト。
   - context の文章。機械で判定できないものだけを書き、失敗の例を添える。
3. 既にある違反が多いときは、増えたときだけ失敗させる。
4. 作った仕組みを、過去の実際の誤りに当てて、止まることを確かめる。手元と CI で同じコマンドを実行する。
5. 例外を設けるときは、違反の行に抑制を書き、理由を添える。例外は利用者の承認を得る。
6. 仕組みにした規則と同じ内容の文章を、context とスキルから消す。
7. 種類ごとにコミットを分ける。opening-a-pr を行う。

**止まる:** 手順 5 で例外を設けるとき。

**返答に書くこと:** 誤りの種類ごとに、根拠、選んだ手段、それより上の手段を選べなかった理由、過去の誤りに当てた結果。
