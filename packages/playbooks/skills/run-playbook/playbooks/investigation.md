# investigation

**担当:** 今あるコードと記録を読んで、問いに根拠付きで答える。成果物は説明か推奨であり、コードの変更ではない。新しく作って比べないと決まらない判断は、prototype が行う。  
調べた結果、コードを変える必要が分かったら、利用者に返し、bug-fix か feature を選び直す。

1. 問いを、確かめられる形に言い直す。「どう動くか」「なぜこうなっているか」「どちらを選ぶべきか」のどれかに分ける。
2. コードと文書を読む。
3. 「なぜ」の問いは、Git の履歴、pull request、ADR から理由を探す。記録から読めない理由は、推測と書く。
4. 実行すれば分かる事実は、実行して確かめる。
5. 答えを書く。
   - 「どう動くか」: 概要、主な概念、処理の流れ、置き場、注意点。
   - 「どちらを選ぶべきか」: 推奨と、選択肢ごとの強みと弱みの表。
   - 根拠には、`<path>:<行の範囲>` を付ける。
6. 調べた結果を残すように頼まれたときは、リポジトリの `.ai-out/` に書く。

**返答に書くこと:** 答え、根拠、確かめていないこと。前提が誤っている問いには、そう書く。
