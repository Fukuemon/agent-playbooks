# bug-fix

**担当:** 報告された不具合を再現し、原因を突き止め、根拠のある最小の修正で直す。  
出荷する変更のすべてを、実行して得た根拠につなげる。「直るかもしれない」変更は仮説であり、出荷しない。根拠に否定された仮説で入れた変更は戻す。

1. 自分で再現する。利用者と同じ画面、コマンド、入力で動かす。`context/testing/verification.md` があれば、その手順で動かす。再現しないときは、条件を絞るか、ログや計測を足して、起きるまで続ける。利用者に再現を頼むのは、自分では届かない理由を具体的に言えるときだけにする。
2. 原因を探す。fix-root-causes を読む。
   - 候補の仮説を挙げ、残りを最も多く減らす確かめ方から順に、実行して否定していく。
   - 状態が分からないときは、推測せず、ログか計測を足して実行中の値を読む。
   - 生き残った仕組みを、実行して得た根拠で確かめてから次へ進む。
3. 修正を決める。原因に対する最小の変更にする。smallest-change を読む。関数の境界をまたぐ修正は、案を比べてから決める。
4. 再現するテストを先に書き、失敗することを確かめる。テストを書く費用が高すぎるときは `skip: <理由>` にする。
5. 修正し、手順 1 と同じ方法で確かめる。元の再現が通ることを確かめる。単体テストが通るだけでは、直ったと言わない。
6. コミットは、失敗するテスト、修正の順に並べる。
7. opening-a-pr を行う。

**止まる:** 手順 1 で、自分では再現に届かない理由があるとき。

**返答に書くこと:** 何が起きていたか、原因、修正、確かめた方法。失敗から成功に変わった再現の出力を、要約せずに貼る。
