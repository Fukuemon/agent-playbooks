# delegate-work

**担当:** 作業を別のセッションに渡す。セッションの作業を丸ごと渡すときは引き継ぎのメモを、1 つの作業をワーカーに配るときはワーカーへの指示を作る。  
自分の作業を止めて続きを残すだけなら、pause-safely を使う。複数の作業を配って取り込みまで回すときは、coordinate-workers がこの playbook を作業ごとに使う。

1. 渡す作業と受け取る側を決める。受け取る側は、別のセッションを立ち上げる手段で起動するワーカーである。サブエージェントとの違いは、スキル run-playbook の共通の規則の「ワーカーとサブエージェント」に従う。
2. 委任の範囲を写す。写すのは、自分が受けた委任（引き継ぎのメモの委任のセクションか、利用者の個人の常設の指示）の範囲の中だけである。
   - 範囲（止まらない操作の名前）、対象（issue と終了の条件）、与えた人と日付をそろえる。利用者の指示の文は、言い換えずに写す。
   - 止まって尋ねる操作と判断、始めない作業も並べる。
   - 自分が受けていない操作を足さない。委任を受けていなければ「なし」と書く。受け取る側は、共通の規則の「止まって尋ねる場面」のとおりに止まる。
3. 引き継ぎのメモを作る。置き場は、リポジトリの主の作業ツリーの `.ai-out/YYYY-MM-DD-<主題>-handoff.md` にする。同じ主題のメモが既にあれば、新しく作らずにそのメモへ足す。セクションは次のとおり。
   - 委任: 手順 2 で写した範囲。
   - 最初に読むもの: 読む順と、基準にするコミット。
   - 今の状態: ブランチ、worktree、pull request、未コミットの変更。書き直してよい。
   - 作るもの: 完了の条件と、未実施のことの扱い。
   - 進め方: 使う playbook と、その中の手順の要点。
   - ほかの作業との順番: 先に終わる必要がある作業と、終わったことを知る合図。
   - 守ること: リポジトリの取り決めのうち、間違えやすいもの。公開しない情報の扱い。
   - 進み具合: 1 行ずつ追記だけ。
   - 返事待ち: 利用者やほかのセッションに尋ねていること。書き直してよい。
   - 決まったこと: 判断の記録。形は共通の規則の「判断の記録」に従う。追記だけ。
   - 次にすること: 済んだ項目に印を付け、消さない。新しい項目は足す。
   - 結果: 手順 5 の完了の通知と同じ中身。
4. ワーカーへの指示を作る。1 つの作業に 1 つの指示を、主の作業ツリーの `.ai-out/` にファイルとして置く。セクションは次のとおり。
   - 対象: issue、ブランチ、worktree の絶対パス。
   - 最初に読むもの: 読む順と、基準にするコミット。
   - 変更: 何をどう変えるか。
   - 制約: 写した委任の範囲、止まって尋ねる場面、ほかの作業と分ける資源（コンテナの名前、ポート、イメージ名など）。
   - 持ち分: 変えてよい worktree とブランチ。取り込みと片付けを、ワーカーと親のどちらが行うか。
   - 観測できる受け入れの条件: 実行するコマンドと、期待する結果。
5. 完了の通知を決める。通知に入れるのは、pull request、取り込んだときのマージのコミット、未実施のことと理由、返事待ちのこと。
   - 通知の手段は、利用者の context か個人の構成に従う。
   - 通知が届かないとき（手段がない、親のセッションが止まっている）は、親の引き継ぎのメモの「進み具合」に 1 行を足すと、指示に書く。
6. 受け取る側を、別のセッションを立ち上げる手段で起動し、メモか指示の絶対パスを渡す。手段は、利用者の context か個人の構成に従う。手段がなければ、絶対パスを利用者に渡して止まる。
7. 渡したことを、自分の引き継ぎのメモの「進み具合」に 1 行で足す。渡した作業を、自分で並べて進めない。

**止まる:** 写す委任の範囲が、受けた委任から読み取れないとき。

**返答に書くこと:** 作ったメモか指示の絶対パス、写した委任の範囲、受け取る側を起動したか、完了の通知の受け方。
