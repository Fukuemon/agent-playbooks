# autonomous-run

**担当:** 決めた終了の条件まで、止まらずに進める。利用者が離れている間の作業や、「終わるまで続けて」の依頼に使う。  
範囲が大きく手順が決まっていない作業は、先にスキル design-playbook で手順を組み、この playbook で回す。

1. 終了の条件を、合否が出る形で書く。テストが通る、再現が通る、数えるスクリプトが 0 を返す。「良くする」「4 時間作業する」は終了の条件にならない。
2. 作業用のブランチで進める。保護するブランチでは作業しない。
3. 1 回ごとに、根拠のある最小の変更をし、終了の条件で確かめる。進んだらコミットし、進まなかった変更は戻す。
4. 回ごとに、判断の記録に 1 行を足す。形は、スキル run-playbook の共通の規則に従う。
5. 途中で見つけた問題（誤りのあるスキル、関係する不具合、結果が揺れるチェック）は、元に戻せる範囲で自分で扱う。本題と分けてコミットし、本題に戻る。
6. 次の場面では止まる。取り消せない操作、利用者だけが決められる判断、行き詰まり。止まるときは pause-safely を行う。
7. 終了の条件を満たしたら止まる。進みが止まっても、それは終わりではない。やり方を変えて続ける。終了の条件を緩めて満たしたことにしない。

**返答に書くこと:** 終了の条件、回した回数、出したものと戻したもの、判断の記録の場所、終了の条件の最後の状態。
