# verification-setup

**担当:** リポジトリに、アプリを利用者と同じ方法で動かして確認する手段を作り、アプリの変化に合わせて保つ。ほかの playbook の「本物で確認する」手順は、この手段を使う。  
手段は利用者のリポジトリだけの知識なので、スキルではなく context に置く。置き場は、アプリに画面があるかで分ける。

| アプリ | 確認の手順を置く文書 | 作るスキル |
| --- | --- | --- |
| 画面がある | E2E のテストは `context/testing/e2e.md`、エビデンスを撮る環境と添付は `context/testing/evidence.md` | setup-e2e |
| 画面が無い（CLI、API、ライブラリ） | `context/testing.md` の Runtime Requirements | なし |

`context/testing.md`、`e2e.md`、`evidence.md` の骨組みは、agent-harness の導入のスキル setup-agent-harness が写す。骨組みが無ければ、導入を先に行うよう利用者に伝える。文書の書き方は、スキル write-context に従う。

## 作るとき

1. リポジトリを読んで、次を答える。コードから読めないことだけを利用者に尋ねる。
   - 利用者が触るもの: 画面、CLI、API、ライブラリ。主なものを 1 つ選び、残りを書き留める。画面があれば、画面のある側として扱う。
   - 起動の方法: リポジトリに書かれた開発用のコマンド、ポート、環境変数、初期のデータ、認証。
   - 動かす方法: 既にある E2E のテストや操作の仕組みを先に使う。なければ、画面はブラウザの操作、CLI は端末の操作、API は HTTP で動かす。
   - 残せる証拠: スクリーンショット、録画、端末の出力、応答、ログ、終了コード、データの状態。
   - 2 つを同時に動かせるか。動かせないなら、そう書く。
2. リポジトリがそのままでは起動しないときは、先に直すか、何が足りないかを利用者に伝える。
3. 画面があるときは、次の順で作る。
   1. スキル setup-e2e で E2E のテストの kit を入れ、`context/testing/e2e.md` を埋める。スキルが無ければ、`skip: e2e のパッケージが無い` とし、3 の 2 に進む。
   2. `context/testing/evidence.md` の Capture Environment、Login and Test Data、Capture Tools を埋める。起動のコマンドと準備ができたと分かる合図、ログインの仕方、テストデータの作り方と片付け、撮るコマンドを、このリポジトリの実際の値で書く。ほかのセクションは、エビデンスを添付するスキル（capture-pull-request）を初めて使うときに埋める。
4. 画面が無いときは、`context/testing.md` の Runtime Requirements に、次の項目を書く。例ではなく、このリポジトリの実際のコマンドと、変わりにくい目印（プロンプトの文字列、ルートのパス、終了コード）で書く。
   - 起動: 起動のコマンドと、準備ができたと分かる合図。止め方。
   - 状態の確認: 動かす価値のある状態か（プロセス、バージョン、ポート、認証）を、何も変えずに確認するコマンド。
   - 操作: 動かし方。
   - 証拠: 何を残し、どこに置くか。利用者と同じ手順で動かし、テストのための近道を使わない。出力だけでなく、書かれたファイルやデータも確認する。
   - 後片付け: 自分が起動したものだけを止める。証拠は消さない。
   - 動かすスクリプトを置いたら、置き場と呼び方。
5. 書いた手順を、最初から最後まで 1 回実行する。起動、状態の確認、主な機能の 1 つの操作、証拠の記録、後片付け。後片付けの後も証拠が残ることを確認する。失敗したら直し、毎回後片付けを実行する。実行していない手順は、できたことにしない。

## 保つとき

1. 前回に確認した後の変更を、`git log` で読む。画面、コマンド、ルート、設定の変更を探す。
2. 作るときに書いた文書の手順を、本物で動かす。
3. アプリが変わって手順が合わなくなったものは、文書を直す。アプリの不具合で手順が通らないものは、文書を直さず、不具合として利用者に伝える。退行を文書の書き換えで隠さない。

**止まる:** 起動に必要な秘密情報や外部のサービスが手元にないとき。

**返答に書くこと:** 埋めたか直した文書のセクション、最初から最後まで実行した結果と証拠の場所、動かせなかった機能とその理由、飛ばした段。
