# reflect

**担当:** 終えた作業から学びを取り出し、次の作業で同じ誤りをしないように、正しい置き場へ書き戻す。  
機械で判定できる学びは、文章にせず、correct に回す。

1. 振り返る作業の範囲を決める。今の会話か、利用者が指した会話やブランチ。
2. 学びの候補を挙げる。次の 3 つの見方で探す。
   - 判断: 長く通用する判断の基準。
   - 使い方: 次の作業で調べ直すことになるコマンド、パス、手順。
   - 抜け: 誤った理由でうまくいった判断、飛ばした確認、利用者に訂正されたこと。
3. 候補ごとに、残すかを決める。次のどれかに当たるものは残さない。
   - 一度きりの出来事。
   - コミットの番号や日付のように、すぐ古くなる事実。
   - 既に context やスキルに書いてあること。
4. 残す学びを、置き場ごとに分ける。
   - このリポジトリだけの取り決め: context。書き方はスキル write-context に従う。
   - 配られた playbook やスキルの誤り: 配布元のリポジトリへの issue か pull request の下書き。利用者のリポジトリに配置された写しは、次の導入で上書きされるので直さない。
   - 機械で判定できる規則: correct に回す。
5. 書き戻す内容を利用者に見せ、明示の指示を受けてから書く。

**止まる:** 手順 5 で、書き戻す指示を待つとき。

**返答に書くこと:** 置き場ごとの学び、残さなかった候補とその理由、correct に回したもの。
