# small-change

**担当:** 設計の判断が要らない変更を、確認してから pull request にする。誤記の修正、設定の値の変更、依存の更新、文書の直しが当たる。  
作業の途中で設計の判断が要ると分かったら、feature に切り替える。

1. 変更する箇所と、その変更が触る範囲を読む。触る範囲が 1 つのモジュールを超えるなら、feature に切り替える。
2. 変更する。smallest-change を読み、頼まれていない整理を混ぜない。
3. 変更が触る範囲のテストとチェックを実行する。コマンドは CONTRIBUTING.md と context に従う。依存の更新では、ビルドと、更新した依存を使う箇所のテストを実行する。
4. 文書を変えたときは、文書のチェックを実行する。
5. opening-a-pr を行う。

**返答に書くこと:** 変えたこと、実行したチェックと結果。
