# review-changes

## 1. 対象を決める

- 差分: 作業用のブランチと統合ブランチの差分。差分を `.ai-out/` にファイルとして書き出し、パスを subagent に渡す。
- pull request: 番号から差分と本文を取得し、同じく書き出す。
- spec: `specs/<issue 番号>-<主題>/` のパス。

## 2. 観点を選ぶ

対象に合う観点だけを選ぶ。全部を毎回は呼ばない。

| subagent | 観点 | 選ぶとき |
| --- | --- | --- |
| review-architecture | 依存の向き、モジュールの境界、責務の置き場 | 複数のモジュールにまたがる差分 |
| review-performance | 計算量、ループの中の入出力、全件の取得 | データ量や処理の回数が変わる差分 |
| review-quality | エラーの扱い、テストの過不足、命名、使われないコード | コードの差分のすべて |
| review-security | 秘密情報、injection、入力の検証、認可 | 外部の入力、認証、ファイルやコマンドを扱う差分 |
| review-spec | 上位の文書との食い違い、未決の論点、受け入れの条件 | spec |

## 3. 並べて呼ぶ

- 選んだ subagent を並べて起動する。各 subagent には、対象のパスと、読むべき context（`context/index.md` から選ぶ）を渡す。
- subagent は読み取りだけを行う。

## 4. まとめる

- 同じ箇所への同じ指摘をまとめる。
- 指摘ごとに、自分でコードか文書を開いて確かめる。確かめられない指摘は「未確認」と付ける。
- 重大度の順に並べる。重大度は、取り込みを止めるもの、直すべきもの、提案の 3 段にする。
- 指摘への対応は自動で行わず、呼び出し元の playbook に返す。

## 返すもの

指摘の一覧（重大度、`<path>:<行>`、根拠、直し方）と、呼んだ観点。指摘がなければ、観点ごとに「指摘なし」と書く。
