# pause-safely

**担当:** 作業を、ほかのエージェントが続きから再開できる形で止める。明示の中断、席を外すとき、会話の要約やコンテキストの上限が近いとき、コンテキストの使用量の知らせを受けたとき、利用の上限が近いとき、取り消せない操作の前で止まるときに使う。  
「続けて」「止まらずに」と言われているときは、明示の中断としては止まらない。ただし、スキル run-playbook の「判断の 3 段」の 3 段目の操作の前では、言われていても止まる。

1. 会話の要約やコンテキストの上限が近いとき、コンテキストの使用量の知らせを受けたときは、要約される前に手順 5 の引き継ぎのメモを書く。要約の後では、要約で落ちたことを書けない。知らせを出す閾値は、利用者の構成に従う。
2. 安全な区切りで止まる。今の手順を終えるか、手前に戻す。新しく始めない。起動中のサブエージェントを止める。起動したワーカーは止めない。
3. 止まるために、取り消せない操作をしない。push と pull request の作成は、利用者が明示に指示したものと、事前の権限の範囲にあるもの以外はしない。この push には、作業用のブランチへの push も含む。
4. 作業を失わないようにする。作業用のブランチで、未コミットの変更を 1 つのコミットにまとめる。type と題は、CONTRIBUTING.md とスキル write-commit に従い、作業の途中であることを題か本文に書く。作業ツリーがビルドやテストを通らない状態なら、そのことをコミットの本文に 1 行で書く。
5. 引き継ぎのメモを書く。置き場は、リポジトリの主の作業ツリーの `.ai-out/<主題>/YYYY-MM-DD-<主題>-handoff.md` にする。同じ主題のメモが既にあれば、新しく作らずにそのメモを更新する。セクションは、delegate-work の、引き継ぎのメモを作る手順に並べたものにする。
   - 「今の状態」「動いているもの」「返事待ち」は、今に合わせて書き直す。
   - 「進み具合」と「決まったこと」は、追記だけにする。
   - 「次にすること」は、済んだ項目に印を付け、新しい項目を足す。項目は消さない。
   - 委任のセクションは、利用者の新しい指示がない限り変えない。
6. 続きを誰が始めるかを決める。止まった理由で分ける。
   - コンテキストの使用量の知らせか、会話の要約やコンテキストの上限が近いことで止まったとき。新しいセッションなら続けられる。
     - ワーカーは、次のセッションを自分で起動しない。メモの絶対パスを、完了の通知と同じ手段で親のセッションに知らせて止まる。
     - 親のセッションは、別のセッションを立ち上げる手段があれば、delegate-work で次の親のセッションに渡す。利用者と対話しているときは、起動する前に利用者に尋ねる。手段がなければ、メモの絶対パスを利用者に渡して止まる。
   - 利用の上限、利用者の答えを待つ論点、3 段目の操作の前、明示の中断で止まったとき。新しいセッションでも同じ理由で止まるので、次のセッションを起動しない。利用の上限なら再開できる時刻を「動いているもの」に書き、ほかはメモの「返事待ち」に書いて止まったままにする。

**返答に書くこと:** 作業の中のどこにいるか、ファイルに残したものと残していないもの、作ったコミットと作業ツリーの状態、引き継ぎのメモの絶対パス、続きを始める人、再開したときの最初の操作。最後の報告ではなく、中断であると書く。
