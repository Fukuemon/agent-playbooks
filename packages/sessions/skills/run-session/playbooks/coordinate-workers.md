# coordinate-workers

**担当:** 依存を並べた複数の作業をワーカーに配り、マージと片付けまでを、終了の条件まで繰り返す。親のセッションがこの手順を進める。  
1 つの作業を渡すだけなら、delegate-work を使う。手順を自動で進めるプログラムや常駐の監視は、このパッケージにはない。

1. 終了の条件を、合否が出る形で書く。「対象の issue の pull request がすべてマージされ、worktree が片付いている」のように書く。置き場は、引き継ぎのメモの「作るもの」にする。メモがなければ、delegate-work の、引き継ぎのメモを作る手順で作る。
2. 作業を並べる。1 つの作業は、単独でマージできる単位にする。作業ごとの依存（先にマージされる必要がある作業）を、メモの「ほかの作業との順番」に書く。依存のない作業は、並べて配る。
3. 並べる作業の資源を分ける。worktree、ブランチ、コンテナの名前、ポート、イメージ名、一時のディレクトリを作業ごとに別の名前にし、ワーカーへの指示の「制約」に書く。ほかの作業や他人が作った資源は消さない。
4. 配る。依存が解けた作業ごとに、delegate-work でワーカーへの指示を作り、ワーカーを起動する。起動したワーカーと端末の識別子を、メモの「動いているもの」に書く。
5. 起動した時点から、端末を読む手段で、すべてのワーカーの様子を見る。完了の通知や pull request の変化だけを待たない。止まったワーカーは、通知も pull request の変化も出さないためである。見る間隔と完了の待ちの上限は、先に bound-every-wait を読んで決める。完了は、ワーカーの完了の通知か、メモの「進み具合」に足された行で受ける。
6. ワーカーの worktree を、親が代わりに書き換えない。次のどれかに当たれば、止まっていると見る。
   - 入力や確認を待っている。委任の範囲と、スキル run-playbook の「判断の 3 段」の 1 段目で答えられるものだけ答える。答えたものは、メモの「決まったこと」に書く。範囲の外の論点は、メモの「返事待ち」に書いて利用者に尋ね、その論点に依存しない作業を進める。
   - 利用の上限に当たっている。再開できる時刻をメモの「動いているもの」に書き、ほかの作業を進める。
   - 同じコマンドが長く終わらない、出力が長く変わらない。ワーカーに状態を尋ね、答えがなければ利用者に尋ねる。
7. 完了を確認する。先に prove-it-works を読む。ワーカーの報告は自己申告として扱う。pull request の CI の結果と差分を自分で読み、受け入れの条件を満たすこと、持ち分の外のファイルを変えていないことを確認する。
   - 判定が「合格」なら手順 8 へ進む。
   - 判定が「要修正」なら、直す点をワーカーに返し、手順 5 に戻る。
   - 同じ作業で 3 周しても「要修正」が残れば、残った点を論点として利用者に尋ね、その作業を止めてほかの作業を進める。
8. マージする。委任の範囲にマージがあれば、CONTRIBUTING.md のマージの方法でマージする。範囲になければ止まって尋ねる。
9. マージした状態を確認する。pull request がマージされたことと、マージ先の CI の結果を見る。マージと片付けを、1 行のコマンドでつながない。マージが失敗しても、片付けが動いてしまう。
10. 閉じた issue の親を確認する。マージで閉じた issue に親の要求があれば、親の子がすべて閉じたかを見る。
    - すべて閉じ、受け入れの条件を確認する子（検証の issue）も閉じていれば、受け入れの条件にチェックを付けて親を閉じる。書き方は、スキル write-issue-pr に従う。issue の書き換えは、委任の範囲にあるときだけ行う。
    - 検証の子が無いか開いていれば、親を閉じない。親が開いたままであることと理由を、メモの「進み具合」に書く。
11. 片付ける。委任の範囲に片付けがあれば、マージに含まれたことを確認したブランチと worktree だけを消す。未コミットの変更や、マージ先にないコミットが残っていれば止まる。片付けたワーカーを「動いているもの」から消す。
12. メモの「進み具合」「決まったこと」「次にすること」を更新し、手順 4 に戻る。終了の条件を満たしたら止まる。
13. 親のセッションが途中で止まるとき（コンテキストの使用量の知らせ、利用の上限、中断）は、pause-safely を行う。起動したワーカーは止めない。次の親のセッションが、session-pickup でメモから再開する。

**止まる:** 委任の範囲にない操作の前。残りの作業がすべて利用者に尋ねた論点に依存するとき。

**返答に書くこと:** 終了の条件と最後の状態、作業ごとの pull request とマージのコミット、閉じた親の要求と開いたままの親、片付けたもの、止まったワーカーとその扱い。推奨で決めた判断、返事待ちの論点、未実施のことと理由、引き継ぎのメモの絶対パス。
