# autonomous-run

**担当:** 決めた終了の条件まで、止まらずに進める。利用者が離れている間の作業や、「終わるまで続けて」の依頼に使う。  
手順が決まっていない作業は、先にスキル design-playbook で手順を組み、組んだ手順をこの playbook で回す。

1. 終了の条件を、合否が出る形で書く。テストが通る、再現が通る、数えるスクリプトが 0 を返す。「良くする」「4 時間作業する」は終了の条件にならない。
2. 作業用のブランチで進める。保護するブランチでは作業しない。
3. 1 回ごとに、根拠のある最小の変更をし、終了の条件で確認する。進んだらコミットし、進まなかった変更は戻す。
4. 回ごとに、判断の記録に 1 行を足す。形は、スキル run-playbook の規則の索引の「判断の記録」に従う。
5. 途中で見つけた問題（誤りのあるスキル、関係する不具合、結果が揺れるチェック）は、元に戻せる範囲で自分で扱う。本題と分けてコミットし、本題に戻る。
6. 作業の中の判断は、スキル run-playbook の共通の規則の「判断の 3 段」で扱う。
   - 1 段目は、推奨の案で決めて進め、判断の記録に残す。
   - 2 段目の論点は、「論点の尋ね方」の形で引き継ぎのメモの「返事待ち」に書いて尋ね、その論点に依存しない作業を進める。全体を止めない。
   - 3 段目の操作の前と、残りの作業がすべて 2 段目の論点に依存するときは、止まる。止まるときは pause-safely を行う。
   - 機能の pull request の動作確認のエビデンスを、利用者が確認するのを待つ間は、2 段目の待ちとして扱い、止まる理由にしない。その pull request はマージせず、ほかの作業を進める。
7. 終了の条件を満たしたら止まる。進みが止まっても、それは終わりではない。やり方を変えて続ける。終了の条件を緩めて満たしたことにしない。

**止まる:** 手順 6 の 3 段目の操作の前と、残りの作業がすべて論点に依存するとき。

**返答に書くこと:** 終了の条件、回した回数、出したものと戻したもの、推奨で決めた判断、返事待ちの論点、判断の記録の場所、終了の条件の最後の状態。
