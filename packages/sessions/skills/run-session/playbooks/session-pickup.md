# session-pickup

**担当:** 前の会話や別のエージェントの作業を、続きから再開する。前の記録を読み、済んだ作業をやり直さない。

1. 会話の要約より先に、引き継ぎのメモを読む。リポジトリの主の作業ツリーの `.ai-out/<主題>/` にある `*-handoff.md` のうち、作業の主題に合うものを開く。メモと要約が食い違えば、メモを優先する。
   - 主題のディレクトリに無ければ、古い置き場の `.ai-out/` の直下の `*-handoff.md` を探す。古い形の再開のメモ（`*-resume.md`）と判断の記録（`*-decisions.md`）が残っていれば、それも読む。
2. ほかの記録を探す。作業用のブランチ、pull request とそのコメント、利用者が渡した会話。長い記録は、サブエージェントに読ませて、時系列の要点だけを受け取る。
3. 今の状態を組み立てる。ブランチと worktree、マージ先との差分（`git log`、`git diff`）、残っている作業、決まった判断、返事待ちのこと。委任のセクションがあれば、その範囲と対象を、スキル run-playbook の規則の索引の「事前の権限」に照らして読む。
4. メモの「動いているもの」を、1 つずつ今の状態で確認する。起動したワーカーは端末を読む手段で様子を見て、外部の待ちは上限の時刻を過ぎていないかを見る。終わっていたものは、結果を「進み具合」に足してから「動いているもの」から消す。
5. 済んだことと残っていることを比べ、再開する場所を決める。済んだ作業の再現や確認を、最初からやり直さない。
6. 前の作業が「済んだ」とした主張のうち、残りの作業が頼るものは、本物で確認する。prove-it-works を読む。前の自己申告は、確認したことにならない。
7. 再開したことを、引き継ぎのメモの「進み具合」に 1 行で足す。古い置き場か古い形のメモから再開したときは、主題のディレクトリに引き継ぎのメモを作り、古いメモの場所を「最初に読むもの」に書く。
8. 残りの作業に合う playbook を選び直し、その playbook に移る。

**返答に書くこと:** 前の作業がどこで止まっていたか、読んだメモの絶対パス、動いているものの状態、引き継いだものとやり直したもの、再開した場所、移った playbook。
